# 内部项目：原生视频交付与用户按需超分增强

Status: resolved

## Problem Statement

内部用户生成视频时，目前方舟链路会按目标档位降低原生生成分辨率，再等待自动超分完成才交付最终结果。即使用户只需要原生视频，也要承担增强的等待；增强失败还可能使整次生成失败并退款，已经生成的视频无法作为普通结果交付。

用户无法在看到成品后，仅对确实需要提升清晰度的视频主动增强。现有视频记录也无法同时呈现原生版与增强版，生成费用和增强费用没有独立的用户语义。ZEX 当前已原生直出，重构需保留其行为，并让视频生成交付统一遵循原生直出的规则。

## Solution

生成页面只提供所选模型实际支持的原生分辨率，直接生成、保存并交付原生视频；生成成功不再依赖自动超分或 MPS 配置。

用户在生成页及共用历史视图中，对本人成功生成的原生视频选择“超分增强”。系统提供高于原生档位且有适用模板的 720p、1080p、4K 目标，展示独立费用，用户确认后发起增强任务。增强版与原生版归属于同一视频记录，可切换预览并分别下载；增强失败只影响增强任务和对应费用。

本项目采用新的空数据库，没有历史成品或在途任务，无需为旧的自动增强链路设计数据迁移或执行兼容。

## User Stories

1. As an 内部用户, I want 按我选择的原生分辨率生成视频, so that 成品规格与我的选择一致。
2. As an 内部用户, I want 只看到所选模型实际支持的原生分辨率, so that 不会误把增强档位当成模型原生能力。
3. As an 内部用户, I want 原生视频保存完成后即可预览和下载, so that 不必等待我没有选择的超分处理。
4. As an 内部用户, I want 在未配置 MPS 时仍能正常生成原生视频, so that 增强服务不会阻断生成交付。
5. As an 内部用户, I want 在看过成品后主动发起超分增强, so that 只增强真正需要提升清晰度的视频。
6. As an 内部用户, I want 从生成页和历史视图增强本人原生视频, so that 不必重新生成或重新上传已保存成果。
7. As an 内部用户, I want 在每个原生视频旁找到增强入口, so that 能准确选择要处理的输出。
8. As an 内部用户, I want 只看到高于原生档位且有匹配模板的增强目标分辨率, so that 不会提交无效或无提升的处理。
9. As an 内部用户, I want 在后台支持时选择 720p、1080p 或 4K 增强目标, so that 能按用途选择所需规格。
10. As an 内部用户, I want 提交前看到本次增强的费用, so that 能决定是否值得增强。
11. As an 内部用户, I want 生成和增强分别计费, so that 不使用增强时只支付生成费用。
12. As an 内部用户, I want 增强按源视频实际时长向上取整到秒计费, so that 费用有明确且可核对的依据。
13. As an 内部用户, I want 增强采用适用于我的账户价格规则, so that 既有账户定价关系保持一致。
14. As an 内部用户, I want 缺少价格或适用模板时不能提交增强, so that 不会发生未经确认的收费或无效处理。
15. As an 内部用户, I want 增强失败时仅退回该增强任务的费用, so that 原生成费用和成功成果不受影响。
16. As an 内部用户, I want 原生版始终保留且可使用, so that 增强等待或失败不会剥夺现有成果。
17. As an 内部用户, I want 在原视频记录中切换原生版和各增强版, so that 可以直接比较和选择结果。
18. As an 内部用户, I want 分别下载原生版和增强版, so that 可用于不同场景。
19. As an 内部用户, I want 不同目标档位的增强版都关联原生视频, so that 不会混淆来源或对增强版继续叠加处理。
20. As an 内部用户, I want 每个增强任务独立显示进度、成功、失败和退款状态, so that 能理解当前处理情况。
21. As an 内部用户, I want 切页、刷新或重新进入后恢复查看增强进度和结果, so that 付费任务不会因浏览器页面变化丢失。
22. As an 内部用户, I want 重复点击或重发请求不会重复创建相同目标的付费处理, so that 不会重复扣费。
23. As an 内部用户, I want 相同原生视频和目标档位已有成功增强版时直接使用它, so that 不必重复支付和等待。
24. As an 内部用户, I want 同一原生视频能够拥有不同目标档位的增强版, so that 可以获得多种规格的成果。
25. As an 内部用户, I want 明确增强失败后能够重新付费重试, so that 能在问题解决后再次尝试。
26. As an 内部用户, I want 请求结果不确定时恢复查询而不是自动创建另一项收费处理, so that 网络问题不会导致重复消费。
27. As an 内部用户, I want 源视频失效、规格不适用或归属不符时在扣费前被拒绝, so that 不会为不可处理的来源付费。
28. As an 内部用户, I want 他人不能增强或访问我的视频成果, so that 视频和费用的归属得到保护。
29. As an 内部用户, I want 隐藏视频记录时连同增强版整组隐藏, so that 历史视图不会残留孤立版本。
30. As an 内部用户, I want 存在处理中增强任务时暂时不能隐藏该记录, so that 付费任务始终能从页面找到。
31. As an 管理员, I want 独立配置各目标档位的增强价格, so that 增强价格不会混入模型生成价格。
32. As an 管理员, I want 使用已有增强模板配置管理适用输入、目标和画幅, so that 用户只能提交实际支持的组合。
33. As an 管理员, I want 能区分生成与增强的状态、费用及结果关联, so that 可以定位失败和核对退款。

## Implementation Decisions

1. 本规格遵循已接受的“内部项目的视频生成交付与超分增强解耦”及“增强任务独立计费，增强版本归属于原视频记录”两项 ADR，使用项目术语表中的原生视频、原生分辨率、增强目标分辨率、增强任务、增强版和视频记录。
2. 调整 Media 的生成能力目录、请求校验和供应商计划，使请求分辨率等于原生生成分辨率。移除新生成流程中的固定降档及自动 MPS 串联；不因超分模板或凭据缺失禁用模型原生能力。现有 ZEX 原生直出行为保留。
3. 原生视频仍经 Storage 归档后才正式交付，以文件标识查询和访问结果。直接交付指未经超分，不是绕过归档或把供应商临时下载地址交给用户。
4. 在 Media 中建立与视频生成相分离的增强任务语义，复用现有持久化任务执行、供应商回执、恢复和退款机制。增强不会重发生成请求、改变原生成成功状态、隐藏原记录或替换原生文件；不能复用具有替换历史行为的“重新生成”作为产品入口。
5. 增强来源明确关联本人成功的视频生成任务及其中的原生输出。只有拥有文件访问权限还不够，服务端还需验证它确实属于该生成结果。首版不接受外部上传、增强版或其他处理任务的输出作为增强来源。
6. 扩展任务与结果关联契约和必要的持久化结构，表达原生输出、增强任务、目标档位、处理状态、费用和退款信息以及成功增强文件的关系。关联以具体原生输出为单位，避免只按生成任务归属而处理错视频。
7. 增强复用现有腾讯 MPS 模板和编排管理。解除只能“480p→720p、720p→1080p、1080p→4K”的固定源档位规划限制，以实际源规格和后台模板声明及验证结果选择适用目标；不承诺任意源视频都能增强到所有目标，也不默认模型有原生 4K 能力。
8. 可用目标限定为 720p、1080p、4K，严格高于原生档位，并有匹配的输入规格、画幅与启用模板。模板和码率由后台配置决定，用户只选目标档位。保留现有编排成功、最终输出尺寸及归档校验，不发布编排中间产物作为用户增强版。
9. 通过 Storage 现有本人视频探测与访问能力取得源视频真实宽高、时长和可读性。模板选择和计费所用视频信息由服务端取得，不能相信客户端传入的来源地址、时长、价格或用户标识。源文件不存在、不可读或不适用时在扣费前拒绝。
10. Billing 独立区分增强消费与生成消费，复用既有账户价格、按用户覆盖、钱包扣费、计价回执和原路退款机制。增强按目标档位的每秒价格乘以源视频实际时长向上取整后的整数秒数计价，5.03 秒按 6 秒。缺少或停用价格时不允许提交，不设置默认免费价格。
11. 增强价格独立进入现有后台定价管理及用户报价流程。用户确认的报价、真正扣费和账务记录须使用一致的目标和计费时长；保持既有计价精度及回执重放语义，不让后来修改的配置重算已经扣费的任务。
12. 以“本人具体原生输出＋增强目标分辨率”限制重复处理：成功版本直接复用，处理中不接受第二项同目标付费处理，明确失败后允许新尝试。每次尝试有独立可恢复身份与收费回执，服务端幂等和并发控制保证重复请求不会重复付费。
13. 沿用既有提交结果不确定时的恢复规则：恢复原任务或等待明确终态，不把网络断开、查询失败或供应商回执不明当作可自动重发付费请求的理由。失败退款只作用于该次增强扣费；退款状态以账务确认结果为准。
14. 用户 API 提供选择可用增强目标、报价、提交、恢复查询和读取关联版本所需的契约；身份来自已有鉴权。增强入口和读取结果都需归属校验，不新增仅供测试的生产接口。
15. 更新共享 API 合同和生成的前端 SDK，保持用户端与管理端使用同一业务含义。Media、Billing、Storage 和既有后台配置接口按实际影响修改，接口路径、内部枚举和表名由实现选择，本规格不固定尚未讨论的内部命名。
16. 用户视频生成页和共用历史视图在所选原生输出旁增加“超分增强”。选择目标、查看费用、确认提交后，在原记录中显示增强状态并切换版本；无可用目标时明确展示不可增强，不能保留一个会提交无效请求的可用按钮。
17. 保留已有单列和多列浏览方式、预览弹窗以及历史加载行为。增强入口在对应视图可到达，版本播放和下载保持归属验证，状态恢复不能仅依赖内存或原生成任务已停止的轮询。
18. 历史隐藏以视频记录整组为单位，隐藏原生版和所有关联增强版；不删除实际文件。任一关联增强任务尚在处理中时，服务端拒绝隐藏，页面说明原因；并发隐藏与增强提交也须保持此规则。
19. 新数据库仍需具备上述任务、关联和计价结构的正常初始化能力；不需要迁移旧成品、在途增强计划或保持旧降档请求语义。初始化失败或缺配置不能被当作免费增强或成功交付。

## Testing Decisions

产品规则及测试边界均已获用户确认。使用以下两条已有的高层边界，不新增测试专用 seam。

1. 主边界为对外 HTTP 行为：从经过已有鉴权的媒体生成、增强及查询入口驱动流程，通过返回状态、本人结果访问、报价、钱包及账务回执验证效果。使用真实应用和持久化执行机制，第三方视频生成与 MPS 采用可控制的本地 HTTP fixture；不能用内存 Billing 替身作为独立扣费、并发幂等和退款的最终证明。
2. 必要的第二边界为用户页面操作：通过现有组件渲染和用户事件测试分辨率选择、增强确认、费用显示、状态恢复、版本切换、下载和整组隐藏。可模拟网络结果覆盖交互，不以此替代后端鉴权、真实账务和持久化验证。
3. 好测试断言外部可见行为和跨边界结果，不绑定私有方法、内部阶段编号、数据库表命名或组件拆分。避免把代码分支逐条复写成实现镜像；优先覆盖从用户请求到成品和费用的完整场景。
4. 后端 prior art 使用已有 MediaApiTest 的鉴权、归属和历史操作测试方式，MediaServiceLoopMysqlTest 的真实服务扣费、归档、退款与重启恢复方式，以及 BillingMediaConcurrencyMysqlTest 的真实账务并发验证。ProductionProviderTest 的本地供应商 HTTP fixture 可复用于高层流程，不作为独立新增公共测试边界。
5. 前端 prior art 使用 ProductionVideoComposer 的模型能力和提交交互测试、VideoTaskResults 的轮询及安全状态展示测试，以及已有视频网格的预览与历史恢复交互测试。后台定价管理沿用 MediaPriceAdminControllerTest 等现有权限和版本冲突测试方式。
6. 至少覆盖：请求原生 720p 时供应商收到 720p，MPS 未配置也能成功保存和交付，且没有自动提交超分；未支持的原生档位被拒绝。保留 ZEX 原生流程，图片和既有其他处理入口不发生行为回退。
7. 至少覆盖：本人成功原生视频可增强；跨用户、非该生成结果的文件、外部来源、增强版来源、缺失或不可读文件、同档或较低目标、不匹配画幅和模板的请求均被拒绝且不扣费。
8. 至少覆盖：5.03 秒按 6 秒计价；目标档位价格独立于生成模型价格；账户价格规则和已确认回执正确复用；缺价不提交。增强失败仅退自身费用，原生成成功状态、原生文件和生成扣费保持不变。
9. 至少覆盖：双击、重放幂等请求、不同请求键并发提交同来源同目标，不会产生重复付费处理；成功结果复用且不收费；不同目标可以形成不同增强版；明确失败可新建重试，退款处理中不把旧请求误当作新消费。
10. 至少覆盖：增强成功文件归档后才可交付，与正确原生输出关联，分别预览下载；失败不清除原生版；供应商回执不明、进程重启、页面刷新和暂时查询失败不会自动创建重复收费处理。
11. 至少覆盖：单列和多列预览都能触达增强入口；费用在确认前可见；原生版和各增强版在同一记录切换；从历史恢复状态；进行中隐藏被拒绝，终态后整组隐藏且已有文件仍保留，并验证并发提交与隐藏的行为。
12. 共享合同生成与类型检查、相关前后端功能测试和构建作为集成校验。真实 MySQL 条件测试若缺环境或被跳过，必须记录为未完成验收，不能把其余测试通过当作真实账务、持久化和恢复场景已经验证。

## Out of Scope

- 外部视频上传后增强，以及对增强版继续增强。
- 同分辨率的画质增强、批量增强、用户选择底层模板或码率，以及 720p、1080p、4K 以外的新增强目标。
- 自动增强开关、默认生成后自动执行超分，以及用增强版替换或删除原生版。
- 将增强结果作为独立历史卡片，或用“重新生成”来替代增强任务。
- 视频记录的实际文件删除、单独隐藏某一增强版、取消在途增强或额外的文件保留策略。
- 取消积分体系、免费增强或整个计费模块重构。
- 旧数据库数据迁移、旧在途任务执行兼容和线上历史成果修复。
- 首页、商务、画布等入口的独立增强 UI 扩展，以及图片生成或其他处理功能的产品改造；共用生成后端应遵循原生交付规则，共用组件须保留既有功能。
- 云资源部署、上线发布和真实付费供应商的效果验收。
