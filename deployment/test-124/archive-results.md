# 内部测试站：生成完成但结果保存失败

`ARCHIVE_REJECTED` 表示生成供应商已经返回结果，但归档没有成功，不能直接按“模型生成失败”处理。先查媒体服务中对应任务的 `Media archive` 日志，再判断是否需要改配置。

2026-10-29 的一次故障由 `STORAGE_ARCHIVE_ALLOWED_HOSTS` 缺少供应商的结果下载域名引起。保存接口返回 HTTP 400，消息为 `archive URL host is not allowed`。供应商日志中的下载地址仍有效，直接读取能得到 JPEG 文件。

本次核验的地址链：

- `oss.curl.mom`：直接返回图片。
- `oss.file-download.life` → `oss.uumail.my`：一次 HTTPS 重定向后返回图片。

内部测试站在 `/etc/xzwl-test-124/storage.env` 的允许列表中补充了以上三个精确域名，保留原有条目。它们是本次已核验的供应商地址，不能当作所有环境的默认值；后续应以配置的供应商实际返回值为准。不要改成通配符或允许任意地址。

排查和恢复顺序：

1. 通过用户与任务 ID 定位，核对 `media_task_result.failure_code`、供应商日志中的输出和存储错误。不要输出手机号、凭据、完整签名 URL 或提示词。
2. 在不重新生成的前提下读取原结果。检查 HTTPS、公共地址、每次重定向的具体域名、文件类型及文件头。仅检查 HEAD 或 Range 可能得到与实际 GET 不同的 CDN 响应，应同时核对与归档客户端一致的 GET。
3. 备份环境文件，只补充已确认的精确域名。在没有任务归档时重启 `xzwl-test-124-storage.service`，检查健康状态；失败则恢复配置。
4. 重放原来的归档调用，沿用 `taskId:RESULT:outputIndex` 幂等键。保存成功后，再验证私有存储中的文件可以读取。
5. 恢复终态任务前，备份任务、结果和版本。在同一事务中检查原状态、版本及失败原因，写入已验证的文件引用，更新任务 JSON 与关系表中的状态，并追加状态审计记录。保留历史可见性及原创建时间。
6. 已完成的退款不重新扣回；补存过程不得调用模型生成、扣费或退款接口。对每条恢复记录检查公开任务响应中的成功状态、结果文件、空失败列表以及退款状态。
