# 领域文档

## 布局

采用 single-context：根目录 `GLOSSARY.md` 保存共享业务术语，
`docs/adr/` 保存架构决策。多个服务和前端使用同一套领域文档。

## 读取规则

- 探索代码前读取 GLOSSARY.md，并读取与当前任务相关的 ADR。
- 文件不存在时静默继续，不创建空文档或占位目录。
- 若以后引入 GLOSSARY-MAP.md，先读取索引，再读取相关领域文档。

## 维护规则

- 由 domain-modeling 在术语明确时创建或更新 GLOSSARY.md；
  只记录业务概念，不放实现细节、任务清单或需求规格。
- 仅对难以逆转、缺少背景会令人困惑、且经过真实权衡的决策记录 ADR。
- ADR 放在 docs/adr/<四位编号>-<主题>.md。
- 需求、任务、测试名称和架构建议使用词汇表中的统一术语。
- 新方案与现有 ADR 冲突时，明确指出冲突及重新讨论的理由。
- 项目的构建与运行方式以 README.md 和实际构建配置为准。
